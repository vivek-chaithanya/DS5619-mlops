## Part 1: CI Workflow (`.github/workflows/ci.yml`)

### Three Jobs with Dependency Chain

| Job | Purpose | Runs On | Key Steps |
|-----|---------|---------|-----------|
| **lint** | Code style & syntax check | `ubuntu-latest` | `actions/checkout@v4` → `setup-python@v5` (3.11) → `pip install -r requirements.txt` → `flake8 src/` |
| **unit-test** | Fast API tests (no Docker) | `ubuntu-latest` | `actions/checkout@v4` → `setup-python@v5` (3.11) → `pip install -r requirements.txt` → `pytest tests/ -q` |
| **integration-test** | Full container test | `ubuntu-latest` | `actions/checkout@v4` → `chmod +x scripts/integration_test.sh` → `./scripts/integration_test.sh` |

### Why `needs: [lint, unit-test]`?

The `integration-test` job is gated behind both `lint` and `unit-test` because:

1. **Cost avoidance**: Docker build + container run takes ~2-5 minutes and consumes significant CI compute. Lint and unit tests complete in ~10-30 seconds.
2. **Fail fast**: If code has syntax errors or failing unit tests, there's zero chance the container will work.
3. **Resource efficiency**: GitHub Actions minutes are limited; don't waste them building broken containers.
4. **Feedback speed**: Developers get lint/unit feedback in seconds, not minutes.

## Part 2: Mock Detector Algorithm (`src/mock_detector.py`)

### Purpose
A lightweight, GPU-free stand-in for a real object detector (YOLOv12/RT-DETRv2/D-FINE). Enables CI testing without heavy ML dependencies.

### Detection Algorithm: Flood Fill on Reddish Blobs

```python
def _is_reddish(pixel):
    r, g, b = pixel
    return r > 120 and r - g > 40 and r - b > 40
```

**Logic**: A pixel is "reddish" if:
- Red channel > 120 (bright enough)
- Red exceeds Green by > 40
- Red exceeds Blue by > 40

This matches the synthetic fixtures generated by `generate_synthetic_fixtures.py` which draws red vehicle-like blobs.

### Flood Fill (Connected Component Labeling)

```python
def flood(sx, sy):
    stack = [(sx, sy)]
    pts = []
    while stack:
        x, y = stack.pop()
        # bounds check + visited check
        if not _is_reddish(px[x, y]): continue
        visited[y][x] = True
        pts.append((x, y))
        # 4-connected neighbors
        stack.extend([(x+1, y), (x-1, y), (x, y+1), (x, y-1)])
    return pts
```

**Algorithm**: Iterative DFS using explicit stack (avoids recursion limits)
- Starts from an unvisited reddish pixel
- Explores 4-connected neighbors (up, down, left, right)
- Collects all connected reddish pixels = one "vehicle blob"
- Time complexity: O(W×H) where W,H = image dimensions
- Space complexity: O(W×H) for visited array + stack

### Bounding Box & Confidence Scoring

```python
xs = [p[0] for p in pts]
ys = [p[1] for p in pts]
bx, by = min(xs), min(ys)           # top-left corner
bw, bh = max(xs) - bx + 1, max(ys) - by + 1  # width, height

# Confidence: based on blob density (reddish pixels / bbox area)
score = min(0.98, 0.4 + len(pts) / (bw * bh + 1))

# Deterministic pseudo-class from box geometry
category_id = (bw * bh) % 14
```

**Scoring rationale**:
- Minimum score 0.4 (base confidence)
- Higher density → higher score (more "vehicle-like")
- Capped at 0.98 (never 100% certain)
- Filtered by `score_threshold` (default 0.3)

## Part 4: Integration Test Script (`scripts/integration_test.sh`)

### Full Container Test Logic

```bash
#!/usr/bin/env bash
set -euo pipefail  # Exit on error, undefined var, pipe failure

IMAGE_NAME="week7-detector"
CONTAINER_NAME="week7-detector-ci"
PORT="8080"

cleanup() {
  docker rm -f "$CONTAINER_NAME" > /dev/null 2>&1 || true
}
trap cleanup EXIT  # Guaranteed teardown on ANY exit

# 1. BUILD
docker build -t "$IMAGE_NAME" .

# 2. RUN (detached, port mapped, auto-remove)
docker run -d -p "$PORT:8080" --name "$CONTAINER_NAME" --rm "$IMAGE_NAME"

# 3. WAIT for /health (max 20s)
for i in $(seq 1 20); do
  if curl -sf "http://localhost:${PORT}/health" > /dev/null; then
    ready=1; break
  fi
  sleep 1
done

# 4. TEST /detect with fixture image
response=$(curl -sf -F "image=@data/fixtures/camera_A_daylight/000.jpg" \
  "http://localhost:${PORT}/detect")
if ! echo "$response" | grep -q "detections"; then
  exit 1
fi
```

### Key Design Decisions

| Decision | Rationale |
|----------|-----------|
| `set -euo pipefail` | Fail fast on any error; catch silent failures in pipes |
| `trap cleanup EXIT` | Guarantees container teardown even on test failure |
| Poll `/health` with timeout | Handles container startup variance; avoids flaky immediate curl |
| `curl -sf` | `-s` silent, `-f` fail on HTTP error codes |
| `grep -q "detections"` | Validates JSON structure without full parsing |
| `--rm` flag | Auto-removes container on stop; no orphaned containers |
